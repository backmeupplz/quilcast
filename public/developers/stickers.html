Inline stickers

For developers. Quilcast, November 2026.

In Quilcast, a sticker can be attached to a cast like a GIF, under its text, or it can sit inside the text, in the line, like a big emoji. This page describes the second way, so that any Farcaster or Hypersnap client that shows Markdown can show these stickers too.

There's no new syntax. An inline sticker is an ordinary Markdown picture whose address is a Quilcast sticker, so a client that doesn't know about inline stickers still shows a picture, and a client without Markdown shows the text as it was typed.

The syntax

gm ![🌅](https://quilcast.com/st/k3V9x_Qa/5f0c2e9a1b7d4c3e8a6f0b12.webp) friends
  • The address is exactly https://quilcast.com/st/<pack>/<sticker>.webp, where <pack> is 8 characters of A-Z a-z 0-9 _ - and <sticker> is 24 lowercase hex digits. As a regular expression, matched against the URL once it's parsed and written back out (so the host is lowercase and there's no :443): ^https://quilcast\.com/st/[\w-]{8}/[0-9a-f]{24}\.webp$. Only that address makes a picture a sticker; any other picture, even one at quilcast.com, stays an ordinary picture.
  • The alt text, between the brackets, is what the sticker says when it can't be shown. Quilcast puts the sticker's emoji there, or sticker when it has none. Any short text works, such as :wave:. It can't hold ] or a line break, and it's best kept free of Markdown's own characters (* _ ~ ` |).
  • Each sticker takes about 70 bytes of the cast's 1,024, so a cast can hold quite a few, but not dozens.

For client developers

  1. Render it in the line. When your Markdown renderer meets a picture whose address matches the pattern above, draw it as an inline image instead of a block picture: about 1.75 times the text's height, with its aspect ratio kept (object-fit: contain in a square box), no frame, sitting on the line like an emoji. The text before and after it stays on the same line. Stickers are WebP, often animated, so let them play. Use the alt text as the image's alt, and as its tooltip if you like.
  2. Don't send it twice. When your composer puts a sticker in the text, don't also add its address as an embed: the cast shows it already, and the embed would take one of its four slots. When you read a cast, hide an embed whose address is also a picture in the text, as you would for any Markdown picture, since another client may still have sent it.
  3. Write it as its alt text where there are no pictures. In notifications, link previews, share cards and other plain-text places, replace the whole ![alt](…) with its alt text, so gm ![🌅](…) friends reads as gm 🌅 friends. Don't use an inline sticker as the cast's preview picture, unless the cast has nothing else to show.

In a client that shows Markdown but not inline stickers, the sticker shows up as an ordinary picture. In a client without Markdown, the reader sees ![🌅](https://quilcast.com/st/…) as typed, with the emoji next to a link to the sticker. Either way, nothing is lost.

Inline custom emojis

The Farcaster Improvement Proposal draft Inline Custom Emoji does the same job a different way, and Quilcast reads it too (as the draft stood on November 23, 2026). There, the text says lfg :check: and the picture is an ordinary embed that carries the label check in the new Embed.emoji_label field. Quilcast draws that picture in the line wherever the text says :check:, as tall as the text, and doesn't show it again under the cast. A shortcode that no embed of the cast carries stays text, as does one inside a link's address. In Quilcast, which shows Markdown, a shortcode inside code also stays text, while Quilcast WASM, which shows no Markdown, draws it in the line. An embed whose label the text never draws is an ordinary picture, as is one whose label got lost in a translation of the cast while that translation is showing. A labelled embed that isn't a picture, such as a video, a page or a mini app, shows as it always would. Where there are no pictures, the shortcode itself is the fallback, so a notification reads lfg :check:.

The two ways differ in what they cost. An inline custom emoji takes one of the cast's four embed slots, while an inline sticker takes none, and a client that knows nothing of either shows the emoji's picture under the text instead of a Markdown address in it. Once the Hypersnap node Quilcast reads from returns emoji_label, Quilcast's composer will send the stickers it puts in the text as inline custom emojis while the cast has slots to spare, named after their emoji (🌅 becomes :sunrise:), and keep any beyond that as inline stickers.

In Quilcast

Turn on Markdown in the composer with its Markdown button, put the caret where the sticker goes and pick one from the sticker button: it goes into the text at the caret. With Markdown off, a picked sticker is attached under the text as before. Packs are made and shared at quilcast.com/stickers, and a Telegram sticker pack can be imported there. Quilcast's code is inline() and styled() in src/shared.ts.
