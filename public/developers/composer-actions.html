Build a composer action

For developers. Quilcast, November 2026.

A composer action is an app people open from the composer in Quilcast. It gets the post they're writing and fills it in: a poll, a GIF or meme maker, a price chart, a link to something your app made, or anything else a small web app can put in a cast. Warpcast used to have these, and this is the same idea built on today's Farcaster mini apps.

An action is a mini app that declares a composerActionUrl in its manifest. Quilcast opens it with the draft in the SDK context, and the app sends the finished post back with the SDK's own composeCast. Nothing else is new, so the same app keeps working in other Farcaster clients, where composeCast simply opens their composer. To make sign-in and notifications work for accounts created on Hypersnap too, see Build mini apps for Hypersnap.

How it works

  1. Someone adds your action from quilcast.com/composer-actions, usually through your own link, https://quilcast.com/composer-actions?add=yourapp.com.
  2. Your action's name and icon then show up under the apps button in their composer.
  3. When they tap it, Quilcast opens your composerActionUrl as a mini app over the composer, with the post they're writing in the SDK context.
  4. Your app does its job and calls sdk.actions.composeCast({ text, embeds }). Quilcast puts that into the post and closes your app, and the person reads it over, edits it if they like, and sends it themselves.

1. Declare it in your manifest

Add composerActionUrl to /.well-known/farcaster.json on your domain:

{
  "accountAssociation": { "header": "…", "payload": "…", "signature": "…" },
  "miniapp": {
    "version": "1",
    "name": "Poll",
    "iconUrl": "https://poll.example.com/icon.png",
    "homeUrl": "https://poll.example.com/",
    "composerActionUrl": "https://poll.example.com/compose",
    "subtitle": "Ask your followers",
    "splashImageUrl": "https://poll.example.com/icon.png",
    "splashBackgroundColor": "#0d0c11"
  }
}
  • composerActionUrl must be an absolute https URL on the same origin as the manifest. Quilcast ignores one that points elsewhere. composerActionUrl is Quilcast's addition to the manifest, and other clients skip fields they don't know.
  • name is the menu label, so keep it short: two words is ideal, and the mini app spec allows 32 characters. iconUrl is a square PNG, drawn at 18 px in the menu.
  • subtitle (or description) is the line shown under the name when someone adds your action by link.
  • Quilcast doesn't require accountAssociation, but other Farcaster clients do, so sign your domain anyway.
  • An app can be a cast action (castShareUrl) and a composer action at the same time.

2. Read the draft

Inside the app, the mini app SDK context has the post the person is writing. Its shape follows composeCast's options, so you can send back what you read. Only text and embeds are taken back, though: parent, quote and channelKey are there to read, and composeCast ignores them.

import { sdk } from '@farcaster/miniapp-sdk'

const ctx = await sdk.context
await sdk.actions.ready()

// the SDK's types don't list this location yet, so compare it as a string
const loc = ctx.location as any
if (loc?.type === 'composer') {
  const { text, embeds, parent, quote, channelKey } = loc.draft
  // text: what's typed so far ('' for an empty post)
  // embeds: the URLs the post embeds: any the composer was opened with (say, a mini app's link, or
  //   https://quilcast.com/train for a train), then its
  //   attachments (photos, videos, GIFs, and links an action added)
  // parent / quote: { type: 'cast', hash } when it's a reply or a quote cast, else undefined
  // channelKey: the channel it goes to, if one is picked, else undefined
  // ctx.user is the signed-in account (the person may pick another of theirs to post this one as)
}

In a thread, text and embeds are those of the post the person had selected when they opened your action, and parent, quote and channelKey are the thread's. Links typed in the text aren't in embeds: they're in text, and they go out as embeds when there's room.

3. Fill it in

When your app is done, send the post back and Quilcast closes your app:

await sdk.actions.composeCast({
  text: `${text}\n\nVote below 👇`.trim(),
  embeds: ['https://poll.example.com/p/8f3a'],
})
  • text replaces the post's text when you send it, so start from draft.text if you only add to it. Leave text out to keep the text as it is. A long cast holds up to 1024 bytes, and the composer won't send more.
  • embeds are added to the post's attachments, after the ones it has. A URL that's already in draft.embeds isn't added twice, so you can send those back with yours, and only https URLs up to 256 bytes long (the hub's limit) count. A link that's both in your text and in embeds is embedded once. A cast holds four embeds on Hypersnap, counting a quote, so the ones past that are left out.
  • Nothing is posted. The person sees the post in the composer and sends it, edits it or throws it away. An image you made has to be at an https URL before you send it, because the embed is the URL.
  • To leave without changing anything, call sdk.actions.close().

Everything else a mini app can do works too, such as signIn, addMiniApp, the wallet, openUrl and haptics. See the cast action doc for what Quilcast supports. Your app stays over the composer until it's done, so viewCast, viewProfile and openMiniApp do nothing while it's open as a composer action.

An example: Poll

poll.quilcast.com is Quilcast's own composer action, built this way. It takes the draft's text as the question, lets the person write 2 to 4 options, keeps the poll on the Quilcast server and fills the post with the question and the poll's link. When the draft is longer than a question can be, it adds only the link and leaves the text alone. That link is a mini app embed with an inline view, so people vote right in the cast, and each account votes once by signing in with Farcaster, which the server checks against the FID's custody address. The page is actions/poll/ and the server part is server/poll.mjs.

In other clients

Other Farcaster clients don't know composerActionUrl yet. If someone opens your app there (from a cast embed, a link or the client's app list), location isn't composer, and composeCast opens that client's composer with your text and embeds. Show a starting screen in that case, rather than assuming there's a draft.

Trust

  • The context isn't proof. Anyone can open your URL, and sdk.context is whatever the host says. Before you spend, store or post anything for someone, have them sign in with sdk.actions.signIn({ nonce }) and verify the result on your server (Build for Hypersnap has the whole check).
  • What your app sees. Your app runs in a sandboxed frame on your own origin. It sees the draft of the post it was opened from, from the moment the person taps your action until your app closes, and the composer closes your app when it closes itself. Adding an action only reads your manifest, through Quilcast's server.
  • What it can't do. It can't send the cast. Only the person can, from the composer, after they've seen what your app wrote. Quilcast reviews the actions on its official list, but not the ones people add by link, and it tells them so.

For client developers

Any Hypersnap or Farcaster client can run the same composer actions. It takes four things:

  1. Read composerActionUrl from the app's manifest, and accept it only as an https URL on the manifest's own origin.
  2. Open it from the composer as a mini app, with location set to { type: 'composer', draft: { text, embeds, parent, quote, channelKey } }. parent and quote are { type: 'cast', hash } with a 0x hash, and the fields that don't apply are undefined.
  3. Answer that app's composeCast by filling in the post instead of opening a new composer. A text string replaces the post's text; each https URL in embeds that isn't attached yet is added while the post has room. Then close the app, and answer the call with { cast: null }, since nothing was posted. Take the call only from the app on screen.
  4. Let the person send it. Never post from a composer action without the person sending it in your composer.

Test it

  1. Serve your app over https on a public address (a tunnel such as cloudflared tunnel --url http://localhost:5173 works while you build).
  2. Open https://quilcast.com/composer-actions?add=your-tunnel-host and tap Add.
  3. Open the composer, tap the apps button and pick your action. Quilcast caches manifests for ten minutes, so to pick up a changed manifest, remove the action and add it again after that.

Get on the official list

The official list at quilcast.com/composer-actions lives in src/composer-actions.json. To add yours, open a pull request (or an issue) on git.borodutch.com/backmeupplz/quilcast with one line: its composerActionUrl, name, icon and a short description. We list actions that work, do what their description says, and don't ask for a wallet signature that the job doesn't need. Until it's listed, share your quilcast.com/composer-actions?add= link, which works for anyone.
