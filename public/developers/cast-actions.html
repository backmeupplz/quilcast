Build a cast action

For developers. Quilcast, November 2026.

A cast action is a button in the ⋯ menu under every cast in Quilcast. People pick the actions they want, and each one does something with the cast it's tapped on: it can check it, tip its author, remind you about it later, reply to it, or anything else a small web app can do.

An action is a Farcaster mini app that declares a castShareUrl in its manifest. That is the same share extension other Farcaster clients show in their share sheet, so a single app works as a Quilcast cast action and as a share target everywhere else, and a mini app that already has a share extension is already a cast action. To make sign-in and notifications work for accounts created on Hypersnap too, see Build mini apps for Hypersnap.

How it works

  1. Someone adds your action, either from the official list at quilcast.com/actions or from your own link, https://quilcast.com/actions?add=yourapp.com.
  2. Your action's name and icon then show up in the ⋯ menu under every cast they see.
  3. When they tap it, Quilcast opens your castShareUrl as a mini app, with the cast in the query string and in the SDK context.
  4. Your app does its job (shows something, asks a question, sends a token, writes a reply) and closes when it's done.

1. Declare it in your manifest

Add castShareUrl to /.well-known/farcaster.json on your domain:

{
  "accountAssociation": { "header": "…", "payload": "…", "signature": "…" },
  "miniapp": {
    "version": "1",
    "name": "Remind me",
    "iconUrl": "https://remind.example.com/icon.png",
    "homeUrl": "https://remind.example.com/",
    "castShareUrl": "https://remind.example.com/share",
    "subtitle": "A nudge about a cast later",
    "splashImageUrl": "https://remind.example.com/icon.png",
    "splashBackgroundColor": "#0d0c11",
    "webhookUrl": "https://remind.example.com/webhook"
  }
}
  • castShareUrl must be an absolute https URL on the same origin as the manifest. Quilcast ignores one that points elsewhere.
  • name is the menu label, so keep it short: two words is ideal, and the mini app spec allows 32 characters. iconUrl is a square PNG (1024×1024 without transparency is what Farcaster clients want), drawn at 18 px in the menu.
  • subtitle (or description) is the line shown under the name when someone adds your action by link.
  • Quilcast doesn't require accountAssociation, but other Farcaster clients do, so sign your domain anyway.
  • webhookUrl is only needed if you send notifications (see Send notifications below).

2. Read the cast

Quilcast opens your castShareUrl with three query parameters, the same ones the share extension spec defines, which means your server can read them before any script runs:

https://remind.example.com/share?castHash=0x5415e243853e…&castFid=2417&viewerFid=12152

Inside the app, the mini app SDK context has the whole cast:

import { sdk } from '@farcaster/miniapp-sdk'

const ctx = await sdk.context
await sdk.actions.ready()

if (ctx.location?.type === 'cast_share') {
  const { hash, text, author, embeds, channelKey, timestamp } = ctx.location.cast
  // author: { fid, username?, displayName?, pfpUrl? }
  // ctx.user is the person who tapped your action
}

Other Farcaster clients send the same shape when someone shares a cast to your app, so you write this once.

3. Do something

Everything a mini app can do in Quilcast, an action can do too. The calls you'll want most are these:

  • sdk.actions.sendToken({ token, amount, recipientFid }) sends a token to the cast's author. Quilcast finds the author's verified address, shows who and how much, and the person's wallet confirms it.
  • sdk.actions.composeCast({ text, parent: { type: 'cast', hash } }) opens the composer with a reply to the cast, which the person can edit before they send it.
  • sdk.actions.addMiniApp() asks to add your app, with notifications, and returns notificationDetails when they're turned on.
  • sdk.actions.signIn({ nonce }) returns a Sign In With Farcaster message and signature that prove who the person is (see Trust, below).
  • sdk.wallet.getEthereumProvider() gives you an EIP-1193 provider for anything else on chain. Quilcast checks each request and asks the person first.
  • sdk.actions.viewCast, viewProfile, openUrl, openMiniApp, swapToken, viewToken, setPrimaryButton and close are all available as well, and so is haptics on phones.

Close when you're done (sdk.actions.close()), so a quick action feels like a menu item rather than a separate app.

4. Send notifications

An action that comes back later, such as a reminder, a price alert or a watch on a thread, uses the same mini app notifications as any Farcaster mini app. A cast action only needs a small part of that flow, though: there's no home screen to build and no user database to keep, just a token, the thing you'll say, and a time.

  1. Add a webhookUrl to your manifest. Quilcast only offers notifications for apps whose manifest has one, and so do other clients. It has to answer 200, but a cast action can leave the events it receives alone (see step 4).
  2. Get a token when someone uses the action. If they already turned notifications on for your app, the context has it. If not, sdk.actions.addMiniApp() asks them to add your app with notifications, and its result has the token once they're on. Ask from a tap, at the moment the action needs it.
  3. Hand the token to your server with whatever the notification needs, such as the cast's hash and when to send it.
  4. Send it. When the time comes, your server POSTs to the token's url. The answer says which tokens worked. Stop using one that comes back in invalidTokens, because that's how a client tells you notifications were turned off or the app was removed, which means a cast action doesn't need to read or verify webhook events at all. Send one in rateLimitedTokens again later: Quilcast takes one notification per token every 30 seconds and 100 a day.
  5. Handle the tap. Tapping the notification opens its targetUrl in your app, with location.type set to notification in the context, and from there sdk.actions.viewCast({ hash }) takes the person to the cast.
// in the action, when someone picks a time
const ctx = await sdk.context
let notify = ctx.client.notificationDetails       // { url, token } once they're on
if (!notify) notify = (await sdk.actions.addMiniApp()).notificationDetails
if (!notify) return show('Reminders come as notifications, so they need to be on.')
await fetch('/api/remind', {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ token: notify.token, url: notify.url, hash: ctx.location.cast.hash, at: Date.now() + 3 * 3600e3 }),
})

// on your server, when it's due
const r = await fetch(reminder.url, {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({
    notificationId: `remind-${reminder.id}`,   // the same id twice within a day is shown once, so retries are safe
    title: 'Reminder',                          // at most 32 characters
    body: '@dwr: the cast you asked about',     // at most 128
    targetUrl: `https://remind.example.com/?castHash=${reminder.hash}`,   // on your own domain
    tokens: [reminder.token],                   // up to 100 per request
  }),
})
const { result } = await r.json()   // { successfulTokens, invalidTokens, rateLimitedTokens }

// the webhook: acknowledge the events; an invalid token tells you the rest
app.post('/webhook', (req, res) => res.json({ ok: true }))

If you'd rather learn about tokens from the webhook, for example to notify people who added your app without using the action, verify each event first with @farcaster/miniapp-node's parseWebhookEvent. Pass it the Hypersnap-aware key check from Build for Hypersnap, though, not the stock one: the stock check only knows keys added on Optimism, so it refuses events from Quilcast and from every account created on Hypersnap.

In Quilcast, notifications from cast actions land in the Mini apps tab of Notifications, and they also arrive as a push when the person has turned push on for mini apps on the Mini apps page. Tapping one opens your app on its targetUrl.

Quilcast signs those events with the person's own Farcaster signer, so turning notifications on costs nothing and works for every account, including ones created on Hypersnap. A webhook that checks keys on Hypersnap (and, optionally, Snapchain) accepts them. If your webhook refuses the event because it only accepts keys added on Optimism, Quilcast sends it again signed with an on-chain app key, which it adds with a small transaction the first time. Accounts created on Hypersnap don't have one, so check keys on Hypersnap if you want to reach them.

A mini app you already have

An existing mini app becomes a cast action once its manifest has a castShareUrl, with no separate app needed. Everyone who has added it in Quilcast finds the action in their ⋯ menu without doing anything, and anyone who adds it later gets the action along with it. Notification tokens belong to your domain, so the token someone gave your mini app already works for notifications about what they did in the action, and the other way round.

Examples

Quilcast's own actions are small, framework-free pages that you can read and copy. Their source is in actions/ in the Quilcast repo.

Spam check

spamcheck.quilcast.com doesn't ask anything. It reads castHash and castFid, asks the free spam.quilcast.com API, and shows two numbers:

const hash = cast.hash.replace(/^0x/, '')
const scores = await fetch(`https://spam.quilcast.com/scores?h=${hash}`).then((r) => r.json())
const users = await fetch(`https://spam.quilcast.com/users?fid=${cast.author.fid}`).then((r) => r.json())
// scores[hash] and users[fid] are 0…1, or missing while the model hasn't read them yet

Tip

tip.quilcast.com offers $1, $5, $10 or any amount, then hands the rest to the host:

const USDC_ON_BASE = 'eip155:8453/erc20:0x833589fcd6edb6e08f4c7c32d4f71b54bda02913'
const r = await sdk.actions.sendToken({
  token: USDC_ON_BASE,
  amount: String(5 * 1e6),          // base units: USDC has 6 decimals
  recipientFid: cast.author.fid,
})
if (r.success) { /* r.send.transaction is the hash */ }

Remind me

remind.quilcast.com is the notifications flow above, end to end. It offers 1 hour to 30 days or any number of minutes, hours, days or weeks, and asks to turn notifications on the first time someone uses it. When the reminder is due, the Quilcast server sends it to the token's URL, and tapping it opens the action again with the cast and an Open the cast button. The page is actions/remindme/ and the server part, which keeps the reminders and sends them, is server/remind.mjs.

Trust

  • The context isn't proof. Anyone can open your URL with any castHash or viewerFid, and sdk.context.user is whatever the host says. Before you spend, store or post anything for someone, have them sign in with sdk.actions.signIn({ nonce }) and verify the result on your server: check the Sign In With Ethereum signature and your nonce, then check that the signing address is the FID's custody address on Hypersnap. Build for Hypersnap has the whole check, which works for accounts created on Hypersnap too.
  • Read the cast from the network when it matters. The cast in the context is a convenience. If your action depends on what it says, fetch it by hash from a Hypersnap node, for example https://haatz.quilibrium.com/v2/farcaster/cast?type=hash&identifier=0x….
  • What Quilcast guards. Your app runs in a sandboxed frame on your own origin. Adding an action only reads your manifest, through Quilcast's server, so nothing about a person or a cast reaches you until they tap it. Every wallet request is shown to the person before their wallet sees it, and Quilcast refuses requests that could take over a Farcaster account. Quilcast reviews the actions on its official list, but not the ones people add by link, and it tells them so.

Test it

  1. Serve your app over https on a public address (a tunnel such as cloudflared tunnel --url http://localhost:5173 works while you build).
  2. Open https://quilcast.com/actions?add=your-tunnel-host and tap Add.
  3. Open any cast's ⋯ menu and tap your action. Quilcast caches manifests for ten minutes, so to pick up a changed manifest, remove the action and add it again after that.

Get on the official list

The list at quilcast.com/actions lives in src/actions.json. To add yours, open a pull request (or an issue) on git.borodutch.com/backmeupplz/quilcast with one line: its castShareUrl, name, icon and a short description. We list actions that work, do what their description says, and don't ask for a wallet signature that the job doesn't need. Until it's listed, share your quilcast.com/actions?add= link, which works for anyone.
